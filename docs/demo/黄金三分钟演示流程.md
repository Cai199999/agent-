# 黄金三分钟演示流程

> 项目：IT 运维工单智能 Agent（agent-gongdan）
> 日期：2026-11-18
> 目标：在 3 分钟内展示“对话报修 → 分诊草稿 → 建单 → AI 分析 → 派单闭环 → RAG 知识引用”。

---

## 1. 演示前检查

| 项 | 要求 |
|---|---|
| 三端 | Web 5180 / Java 8200 / Python 8300 均可访问 |
| 账号 | `admin`、`engineer1`，密码在项目根 `.env` |
| 知识 | 已上传 4 篇演示知识：电梯、消防水泵、门禁、空调 |
| 浏览器 | 准备两个窗口/隐身窗口，分别登录 admin 与 engineer1 |
| 数据 | 工单列表已有 16 条，状态覆盖待受理/待接单/处理中/已关闭 |
| 页面 | 提前登录，避免现场输密码；关闭无关标签页 |

> 不在演示中删除知识、停止共享 MySQL/Redis/MinIO，也不要用“闭环测试工单”这类测试标题做主线。

## 2. 时间线

### 0:00–0:20 开场：工单列表

1. admin 登录，默认进入工单管理。
2. 展示状态筛选、时间筛选、工单数量与类型分布。
3. 说明：这是一个“AI 辅助 + 人确认”的工单平台，不是纯聊天机器人。

### 0:20–1:00 对话报修与人在回路建单

1. 左侧进入“AI 助手” → 新建会话。
2. 输入：

   > A栋2号梯困人了，请尽快处理

3. 展示：
   - 流式回答与“处理过程”时间线；
   - 分诊结果：故障报修、高置信度；
   - 工单草稿卡：电梯、紧急、A栋 2号。
4. 点击“确认建单”，展示“已建单 WT...”与工单号。
5. 强调：**AI 不自动建单，必须人工确认。**

### 1:00–1:35 工单详情与 AI 分析

1. 打开刚创建的工单详情。
2. 点击“开始 AI 分析”。
3. 展示：
   - 风险等级 HIGH；
   - 可能原因、建议动作；
   - “知识依据”引用。
4. 点击知识引用 Tag，展示可直接下载原文。
5. 点击“查看推荐方案 →”，展示跳转 AI 助手并预填问题。

### 1:35–2:10 派单与闭环

1. admin 在工单详情点击“派单”，选择“张工（运维）”。
2. 切到 engineer1 窗口：刷新工单列表 → 接单 → 解决，填写“已到现场安抚乘客并恢复电梯，门锁正常”。
3. 切回 admin：验证通过 → 关闭。
4. 展示工单时间线与右上角通知铃铛。

> 若时间紧张，可只演示“派单 + 接单”，把解决/关闭口头说明。

### 2:10–2:40 知识库与 RAG

1. 进入“知识库”，展示文档列表：电梯、消防水泵、门禁、空调。
2. 检索：`消防水泵多久巡检一次？`
3. 展示命中结果与相似度。
4. 回到 AI 助手提问同样问题，展示回答中的知识引用。
5. 强调：知识库是权威来源，回答带引用，可下载原文。

### 2:40–3:00 稳定性与降级说明

1. 打开 `http://127.0.0.1:8200/api/v1/health/ai`，展示 `UP`。
2. 口头说明：
   - Python 故障时自动熔断，规则分诊兜底；
   - 对话失败可“改用表单报修”；
   - Milvus/检索失败会降级为纯 LLM，不阻断主流程。
3. 不在现场停 Python，避免演示事故；可提前录制备用视频。

## 3. 推荐话术

- “AI 负责理解、检索和建议，Java 负责权限、事务和审计，所有写操作都要人确认。”
- “知识库回答带引用，能点开原文，不是模型凭空生成。”
- “即使 AI 服务挂了，工单主流程仍然可用。”

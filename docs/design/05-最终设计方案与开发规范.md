## 2. 最终项目定位与范围

### 2.1 项目定位

建设一个**可部署、支持高并发演进的企业级 IT 运维工单智能 Agent**：

- 前端 Vue3 + TypeScript + Element Plus。
- Java BFF 负责业务、权限、工单、会话持久化与对外 API。
- Python AI 服务负责意图识别、分诊、RAG、LangGraph 工具编排与向量检索。
- MySQL 存业务与元数据，Redis 做缓存/限流/可选黑名单，MinIO 存附件与知识原文，Milvus Lite 存向量。
- 六边形架构，端口抽象，MVP 妥协保留升级路径。
- 严格资源隔离，不影响 `vibe-platform` 等共享中间件的其他项目。

### 2.2 MVP 范围（P0）

| 模块 | MVP 内容 |
|---|---|
| M0 平台基础 | 统一响应/错误码、trace_id、健康检查、日志脱敏、OpenAPI、CORS/限流 |
| M1 认证与用户 | 登录、JWT、refresh 轮转、CSRF、当前用户/角色/权限 |
| M2 工单管理 | 表单建单、列表、详情、状态流转、评论、附件、完结、操作日志 |
| M3 派单与流转 | 直接派单、认领、转派基础能力 |
| M4 AI 会话 | 会话、消息、POST SSE、历史存储、引用、会话关联工单 |
| M5 意图识别与分诊 | 意图/实体/置信度、草稿、人在回路确认、低置信转人工 |
| M6 知识库与 RAG | 文档上传、解析分块、Embedding、Milvus 检索、引用、无命中兜底 |
| M7 Agent 工具 | 建单、查单、我的工单、检索知识、工具审计 |
| M8 降级与容错 | AI 熔断、LLM 超时、Milvus/Embedding 降级、规则兜底 |
| M15 前端核心 | 登录、Layout、Axios、工单列表/提交/详情、知识库、AI 对话 |

**MVP 功能项统计**：156 个功能项，其中 P0 69、P1 52、P2 35（以 01 §5.17 为准）。

### 2.3 拓展范围（P1/P2）

- 派单看板、抢单池、转物业部。
- 站内通知、系统弹窗、SLA 预警、语音播报（P2）。
- 统计报表、满意度、SLA 达成率。
- 业户/房号/资源图、设备台账/巡检。
- 系统管理、审计、AI 参数配置。
- 通知/SLA GET SSE（P1）。

### 2.4 明确不做

- 完整物业 ERP（收费、合同、财务、门禁等）。
- 多租户运行时（仅预留 `tenant_id`）。
- 原生移动端 App、真实语音网关。
- Milvus Standalone（本期 Milvus Lite）。
- 修改共享中间件配置或操作其他项目。

## 4. 最终架构定稿

### 4.1 总体架构

```text
Vue3 + TS + Element Plus (5180)
        │  HTTP/SSE + JWT
        ▼
Java BFF 8200（六边形）
  ├── MySQL agent_gongdan_db
  ├── Redis 前缀 agent_gongdan:
  ├── MinIO bucket agent-gongdan
  └── Python AI 8300（六边形）
        ├── Milvus Lite（知识/工单向量）
        ├── DeepSeek（LLM）
        └── SiliconFlow（Embedding bge-m3 / 1024）
```

- Java 是业务数据唯一写入方。
- Python 无状态（Milvus Lite 数据除外），不直连 MySQL。
- 前端只访问 Java；不直连 Python。
- 内部调用双向：Java→Python（J2P Token）、Python→Java（P2J Token）。

### 4.2 分层与依赖

| 层 | Java | Python | 前端 |
|---|---|---|---|
| 领域层 | `domain/` 纯业务 | `domain/` 纯业务 | — |
| 应用层 | `app/ports` + `app/service` | `app/ports.py` + `service.py` + `policies.py` | stores/composables |
| 适配层 | web/persistence/ai/storage/cache/notification | api/models/stores/gateways/tools/agent | views/components/api |
| 组装根 | Spring Config | `main.py` | `main.ts` |

**硬规则**

1. `domain` 不依赖框架/数据库/HTTP。
2. `app` 只依赖 domain 与 ports。
3. 适配器实现端口，可替换（Milvus Lite→Standalone、模型/平台切换）。
4. Python 不写 MySQL；Java 不绕过端口直接调 SDK 业务逻辑。
5. 前端不直连 Python；不把密钥放入 `VITE_*`。

### 4.3 关键数据流

| 流程 | 路径 |
|---|---|
| 对话建单 | Vue → Java SSE → Python Agent → 工具回调 Java 建单 → `chat_session_ticket` + `ticket.triage_id` |
| RAG 问答 | Java → Python → Embedding → Milvus → LLM → 引用回传 → Java 落库 |
| 人工工单 | Vue → Java → MySQL；事件/时间线/派单历史 |
| 知识入库 | Java 上传 → `file_object` → Python 解析/分块/向量化 → `vector_index_job`/`vector_object` |
| 相似工单 | Java → Python 查 ticket collection → 返回 ticket_id+score → Java 批量查询组装 |
| 建单溯源 | `source_ref_*` + `triage_record` + `chat_session_ticket` + `chat_tool_call.result_ticket_id` |

### 4.4 部署拓扑

| 环境 | 拓扑 |
|---|---|
| dev | Vite 5180 → Java 8200 → Python 8300；MySQL/Redis/MinIO 共享实例；Milvus Lite 文件 |
| prod | Nginx/HTTPS → Java 多实例；Python 单实例（Milvus Lite）；应用可选容器化；所有 ingress 屏蔽 `/internal/**` |

## 5. 风险与降级机制

### 5.1 风险清单

| 编号 | 风险 | 影响 | 概率 | 应对 | 阶段 |
|---|---|---|---|---|---|
| R1 | AI 服务宕机 | 对话/分诊不可用 | 中 | 熔断 + 表单建单 + 规则分诊 | P0 |
| R2 | LLM 超时/限流 | 回答失败/成本 | 中 | 重试 + 熔断 + 降级提示 | P0 |
| R3 | Milvus Lite 故障 | RAG/相似不可用 | 中 | 跳过检索；可重建 | P0 |
| R4 | Embedding 不可用 | 无法向量化 | 中 | 跳过 RAG；关键词/无引用回答 | P0 |
| R5 | Redis 不可用 | 刷新/限流/缓存异常 | 中 | refresh fail-closed；本地限流；缓存 miss | P0 |
| R6 | MySQL 不可用 | 业务不可用 | 低 | 健康检查、告警、恢复；不降级写 | P0 |
| R7 | MinIO 不可用 | 附件/知识原文不可用 | 低 | 附件可选；返回 50003；重试 | P0 |
| R8 | 共享中间件争用 | 性能波动 | 中 | 独立前缀/库/bucket；限 TTL；监控 | P0 |
| R9 | 无物理外键产生孤儿 | 数据不一致 | 中 | 应用校验 + 对账 + 差异表 | P1 |
| R10 | 无 JOIN 导致 N+1 | 性能下降 | 中 | 批量 IN + Map 组装 + 压测 | P0 |
| R11 | 提示词注入/工具越权 | 安全 | 中 | 工具白名单、参数校验、审计 | P0 |
| R12 | JWT/refresh 泄露 | 账号安全 | 低 | 内存存储、HttpOnly、CSRF、轮转、黑名单 | P0 |
| R13 | 内部 Token 泄露 | 横向越权 | 低 | 方向拆分、轮换、内网、ingress 屏蔽 | P0 |
| R14 | workerId 冲突/时钟回拨 | 主键重复 | 低 | 部署登记、回拨保护、告警 | P0 |
| R15 | Milvus Lite 单进程 | 无法水平扩展 | 高（演进） | Standalone 升级路径 | P1 |
| R16 | 磁盘仅 7GB | 构建/数据增长 | 中 | 监控、清理、镜像/依赖控制 | P0 |
| R17 | 端口冲突 | 启动失败 | 低 | 启动前 `ss -ltn` 复核、登记 | P0 |

### 5.2 AI 服务宕机降级方案

| 故障 | 检测 | Java 行为 | Python 行为 | 用户感知 | 恢复 |
|---|---|---|---|---|---|
| Python 整体不可达 | 健康检查/连接失败/熔断 | 熔断打开；对话返回 `30001`；表单建单可用；规则分诊 | — | 提示 AI 暂不可用，可继续建单 | 半开探测成功自动恢复 |
| LLM 超时/5xx | 超时/错误码 | SSE `error` `30002`；助手消息 `FAILED` | 重试 2 次后返回 | 提示重试，保留已生成内容 | 熔断半开 |
| LLM 429 | 状态码 | 限流提示；不无限重试 | 退避重试 | 稍后重试 | 配额恢复 |
| Milvus 不可用 | 连接/查询异常 | 相似返回 `30006` 或空；知识检索降级 | 跳过向量检索，标记 `degraded` | 提示知识/相似检索暂不可用 | 重建/重启后恢复 |
| Embedding 不可用 | 调用失败 | — | 跳过向量化；无引用回答或转人工 | 回答无引用 | 重试/切换平台 |
| **SiliconFlow 整体不可用** | 连接失败/持续 5xx/配额耗尽 | **无检索纯对话**；相似工单返回空列表且不报错；知识检索无命中 | 跳过 Embedding/RAG；仅 LLM 回答 | 回答无引用；相似为空；提示知识检索暂不可用 | 恢复后补索引/补召回 |
| **向量任务失败 / ticket collection 为空** | `vector_index_job=FAILED` / 集合无数据 | 相似工单返回 **空列表 + `degraded=true`**，不返回 500/30006；工单主流程不受影响 | 任务标记失败；不阻断查询 | 相似结果为空，无错误弹窗 | 重试入库/重建索引 |
| 工具调用失败 | 超时/错误 | 返回 `30003`；事务回滚/补偿 | 记录失败，回复未完成 | 不产生脏数据 | 重试（幂等） |
| Agent 超步 | 步骤上限 | 返回 `30004` | 停止并返回 | 提示简化问题/转人工 | — |

**关键原则**

1. AI 故障不得阻断建单、查单、工单流转。
2. 降级必须有明确用户提示与 `degraded=true` / 错误码。
3. 工具调用失败不得产生半成品工单；使用幂等键与事务补偿。
4. 熔断恢复采用半开探测，避免雪崩。
5. 所有降级事件记录 `traceId`、原因、持续时长，P1 接入告警。

#### 5.2.1 MVP 轻量落地（2026-11-18）

开发阶段不追求完整熔断平台，采用“**轻量自愈 + 明确兜底**”：

| 能力 | MVP 实现 | 验收口径 |
|---|---|---|
| 熔断 | Java `AiAvailabilityGuard`，按 `chat`/`triage`/`analysis`/`retrieval` 分 scope；连续 3 次失败打开 15s；半开失败翻倍至 60s；成功即关闭 | 停 Python 后连续请求快速失败，不长时间阻塞；恢复后首个请求自动探测成功并关闭 |
| 自愈 | 打开到期放行 1 个探测请求 | 无需重启 Java；探测成功即恢复 |
| 分诊兜底 | Python 分诊失败时，Java 关键词规则生成低置信度草稿（`model=rule-fallback`），人在回路确认后建单 | Python 宕机时对话失败，但用户仍能看到草稿卡并确认建单 |
| 前端兜底 | 对话失败提示 + “改用表单报修”按钮；AI 状态绿/黄条 | 失败气泡可一键跳到工单创建弹窗 |
| 检索降级 | 知识/相似检索失败返回空 + `degraded=true`，不阻断对话 | Milvus/Python 故障时仍可纯 LLM 回答 |
| 健康检查 | `GET /api/v1/health/ai` 返回 `UP`/`DEGRADED` 与各 scope 状态 | 故障时前端可展示黄色提示条 |

> 演练记录：`docs/reports/2026-11-18-M8降级自查与演练报告.md`（Python 宕机、熔断、自愈、Milvus 空索引降级均实测通过）。

**明确不做（P1）**：滑动窗口失败率、慢调用统计、自动重试、舱壁配额、Micrometer 熔断指标、告警。**当前保留自研实现，不替换 Resilience4j**；仅当未来需要上述能力时，再以 Resilience4j 实现同一 `AiAvailabilityPort`，业务代码不改。

### 5.4 数据一致性与对账

- 无物理外键：应用层存在性校验 + 同事务写入 + 幂等键 + 唯一索引。
- 每日对账（P1）：孤儿引用写入 `sys_reconcile_diff`；MVP 只报告不自动修复。
- 对账范围：工单-业户/房号/设备、附件-文件、会话-工单、分诊-工单、知识-分块、向量映射。
- 删除编排：软删除主记录 → 异步清理对象/向量 → 审计；禁止级联删除。
- 向量以 MySQL 为事实源；Milvus 可重建；旧版本向量在新版本成功后删除。

### 5.5 安全风险与措施

| 风险 | 措施 |
|---|---|
| XSS 窃取 access token | access 仅内存；Markdown 渲染 DOMPurify；CSP（P1） |
| CSRF | refresh/logout 使用 `SameSite=Lax` + `X-CSRF-Token` 双提交 |
| refresh 重放 | 一次性轮转；旧 jti 黑名单；重放撤销整个家族 |
| 内部 Token 泄露 | 方向拆分、current/next 轮换、内网、所有 ingress 屏蔽 |
| 提示词注入 | 用户内容分隔、系统提示词约束、工具白名单、参数二次校验 |
| 工具越权 | 按角色/dataScope 裁剪工具；高危操作确认 |
| PII 泄露 | 手机号加密 + HMAC 查询 + 脱敏展示；日志脱敏 |
| 文件上传攻击 | 10MB、类型白名单、魔数校验、随机 object_key、预签名 |
| SQL 注入 | MyBatis-Plus 参数化；禁止拼接 SQL |
| 依赖漏洞 | 版本锁定；P1 依赖审计 |

### 5.6 资源与容量风险

- 宿主内存 7.2GiB，vibe-platform 已占约 3.4GiB；本项目 JVM 256–512MB、Python 300–500MB、Milvus Lite 轻量。
- 磁盘剩余约 7GB：依赖、索引、日志需控制；Milvus 数据目录上限与清理策略。
- 共享 Redis `maxmemory=0 + noeviction`：应用必须强制 TTL、容量上限，不能依赖淘汰。
- 端口 8200/8300/5180 启动前 `ss -ltn` 复核；冲突立即停止。
- 禁止修改/重启共享容器；禁止 `pkill`/`killall`/`fuser -k`。

### 5.7 应急预案与回滚

| 场景 | 步骤 |
|---|---|
| AI 服务异常 | 确认熔断状态 → 保留表单建单 → 检查 Python/LLM/Milvus → 半开恢复 → 记录复盘 |
| MySQL 异常 | 停止写入 → 健康检查/告警 → 联系共享中间件负责人 → 恢复后校验 → 对账 |
| Redis 异常 | refresh/logout fail-closed；access 继续；本地限流；恢复后清理过期 key |
| Milvus 数据损坏 | 停止索引任务 → 从 MySQL `kb_chunk`/工单重建 → 切换新版本 → 删除旧向量 |
| 磁盘不足 | 停止非必要任务 → 清理日志/构建缓存 → 评估数据增长 → 扩容由用户决定 |
| 安全事件 | 吊销 refresh/token 家族 → 轮换内部 Token → 审计日志 → 修复 → 复盘 |
| 发布回滚 | 应用版本回滚；数据库只向前修复（Flyway 不回滚）；向量/文件按版本切换 |

**备份（P1）**：本项目库 `mysqldump`、MinIO bucket 同步、Milvus 数据文件快照；RPO/RTO 在第 9 节待确认。

### 6.10 性能与并发规范

- 前端普通请求 10s；SSE 空闲 60s；ping 15–20s。
- Java→Python：连接 1s；对话 30s/空闲 60s；分诊 10s；相似 8s；检索 5s。
- Python→Java：连接 1s；读 5s。
- 重试仅幂等接口；SSE 首字节后不重试。
- 连接池：Hikari 5–20；WebClient/httpx 上限；JVM 256–512MB。
- 限流：用户/IP/接口/SSE 连接；Redis 令牌桶 + 本地兜底。
- 禁止深分页 OFFSET；消息/事件走 cursor。
- 大字段不进列表查询；批量 IN ≤500。

## 附录 F：Agent 工具平台演进蓝图

> 定位：从“AI 辅助工单”演进为“一个对话框解决问题”的 Agent 工具平台。对话是入口，不替代既有 UI；高风险动作保留表单与人机确认。
> 策略：**设计现在预留，代码后置**；工具契约必须依赖稳定的业务 API。不做独立“中台系统”，不做通用工具市场。

### F.1 演进原则

1. Java 仍是业务唯一写入方；Agent 通过内部 API 调用工具，不直连数据库。
2. 工具契约依赖稳定 API；基础功能未稳定前只预留边界，不大规模工具化。
3. 工具权限与 dataScope 由 Java 强制执行，Agent 不得绕过业务规则。
4. 高风险写操作必须二次确认；所有工具调用可审计、可追溯、可补偿。
5. 不做独立数据中台/测试中台；先做模块化能力，满足触发条件再拆分。

### F.2 分层模型

| 层 | 职责 | 当前落点 |
|---|---|---|
| 工具契约层 | Tool Spec、输入/输出 Schema、权限、风险级别 | Python `domain/tool.py`、`app/ports.py` 占位 |
| 上下文层 | 用户/角色/数据范围/页面/选中对象/业务上下文 | Java `ContextProvider` 预留、`ticket`/`chat_session_ticket` |
| 编排层 | LangGraph 多步规划、工具选择、失败恢复 | Python Agent 骨架 |
| 权限与确认层 | 工具级 RBAC、dataScope、二次确认、审计 | Java 权限码 + `chat_tool_call` |
| 评测与可观测层 | 工具成功率、任务完成率、延迟、成本 | `triage_record`、`ai_call_log`、`chat_tool_call` |
| 插件/生态层（P2） | 外部系统工具、工具市场 | 暂不做 |

### F.3 工具契约规范

每个工具必须具备：

| 字段 | 说明 |
|---|---|
| `name` | 稳定工具名，如 `ticket.create` |
| `description` | 面向模型的能力说明与边界 |
| `input_schema` | 结构化参数 Schema，禁止自由文本拼接 |
| `output_schema` | 结构化结果，含业务对象 ID 与摘要 |
| `permission` | 所需权限码 |
| `data_scope` | SELF/DEPT/ALL，运行时由 Actor 决定 |
| `risk_level` | LOW/MEDIUM/HIGH |
| `requires_confirm` | 高风险/写操作是否需用户确认 |
| `idempotent` | 是否幂等；写工具必须支持幂等键 |
| `timeout` / `max_retries` | 调用预算 |
| `audit` | 入参摘要、结果状态、traceId |
| `version` | 工具契约版本，变更需兼容策略 |

### F.5 统一上下文模型

Agent 可获取（按权限过滤）：

- Actor：用户 ID、角色、部门、dataScope。
- 页面上下文：当前页面、选中工单/业户/房号/设备。
- 业务上下文：工单状态、SLA、历史事件、知识引用、相似工单。
- 会话上下文：最近消息、摘要、已确认动作。
- 约束：不得注入无权限数据；上下文最小化；敏感字段脱敏。

### F.6 执行策略

1. **Plan**：LangGraph 解析意图并生成步骤计划，限制 `AGENT_MAX_STEPS`。
2. **Validate**：校验工具白名单、参数 Schema、权限与 dataScope。
3. **Confirm**：高风险写操作展示草稿/影响范围，用户确认后执行。
4. **Execute**：通过 Java 内部 API 执行；写工具携带幂等键。
5. **Verify**：检查业务结果与状态；失败进入补偿/回滚。
6. **Audit**：记录工具名、参数摘要、结果、耗时、traceId、Actor。
7. **Fallback**：工具不可用时转人工/表单，不静默失败。

### F.7 权限与安全

- 工具级 RBAC + 数据范围；内部调用仍执行 Java 权限校验。
- 工具白名单；禁止 Agent 自行发现未授权工具。
- 提示词注入防护：用户内容分隔、工具参数二次校验、禁止执行文档中的指令。
- 高风险动作（派单、关闭、权限变更、批量操作）必须确认。
- 所有写工具幂等；失败可补偿；禁止半成品业务对象。

### F.8 评测与量化指标

| 指标 | 说明 |
|---|---|
| 工具选择准确率 | 选中正确工具的比例 |
| 参数准确率 | 工具参数与用户意图一致的比例 |
| 任务完成率 | 多步任务最终完成的比例 |
| 工具成功率 | 工具调用成功/总调用 |
| 人工接管率 | 转人工/总会话 |
| 回滚/补偿率 | 失败后回滚或补偿的比例 |
| P95 延迟 | 单工具与整任务 |
| token 成本 | 每任务/每会话 |

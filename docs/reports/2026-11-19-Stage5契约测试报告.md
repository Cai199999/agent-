## 5. 关键覆盖点

### 5.1 Manifest / Agent Card

- 必需字段齐全；`protocol=agent-task-v1`；SYNC/ASYNC 均声明；
- 18 个能力无重复，读能力 `requiresConfirm=false`，写能力全部 `true`；
- Agent Card 与 Manifest 版本、协议、skills 一致；securitySchemes 不泄露密钥。

### 5.2 鉴权与越权

- 缺失/错误 `X-Internal-Token` → 401/10001；
- 非法委托令牌 → 401/10001；
- 委托令牌声明的 Actor 覆盖可伪造的 `X-Actor-*`；
- 非任务所有者读取/确认/订阅 → 403/10003；
- 委托 scope 外的能力 → 403/10003；委托令牌禁止二次委托。

### 5.3 Task API 与幂等

- 响应字段集合与类型稳定；`traceId` 从 `X-Trace-Id` 透传；
- `clientTaskId` 按 Actor 幂等，不同 Actor 不串任务；
- 未知能力 → 任务 `FAILED` + `60001`（不写业务数据）；
- 非法 `executionMode`、空 `taskType` → 400/60001。

### 5.4 确认令牌与取消

- 写任务提交后 `WAITING_CONFIRM`，未确认不返回工单、不落库；
- 错误令牌、非所有者确认 → 403/10003；
- 正确确认 → 执行成功、令牌清理；重复确认 → 409/20002；
- `WAITING_CONFIRM` 可取消，取消后令牌失效，再确认 → 409/20002；
- 异步写任务确认后进入队列并最终成功。

### 5.5 事件与 SSE

- 事件历史顺序 `PENDING → RUNNING → SUCCEEDED`，字段齐全，事件 ID 递增；
- SSE 先回放历史 `task-event`，终态发送 `done` 并关闭；非所有者 → 403。

### 5.6 双跑与独立实例

- 原有 `/api/v1/auth/login`、工单列表、AI 健康检查正常；
- Task API 确认创建的真实工单可通过原有用户端详情接口读到；
- `agent` Profile 独立实例：manifest/card 可用，用户端 API 404，`/actuator/health` 正常。

## 7. 仍存在的边界

1. 契约测试为运行时黑盒 + 单元测试组合，**尚未接入 CI 门禁**；
2. 独立实例仍复用同一构建产物、数据库与进程内队列，**未物理拆服务**；
3. 队列仍为进程内线程池，进程崩溃后 `PENDING/RUNNING` 任务不自动恢复；
4. SSE 仍为数据库轮询；
5. `inputTokens` / `outputTokens` / `costMicros` 仍为预留字段，未接真实 LLM 计量；
6. 未引入 Pact 等消费者驱动契约工具，契约以 Manifest + 字段集合冻结为主。

# E2E 验收测试指南

> 项目：IT 运维工单智能 Agent（agent-gongdan）
> 版本：Phase 1（含 M8 轻量降级）
> 日期：2026-11-18
> 目标：由用户按本指南亲自完成“对话报修 → AI 分析 → 确认建单 → 派单 → 处理完毕 → 知识入库”的全链路验收。

## 0. 前置检查

### 0.1 服务与端口

| 服务 | 地址 | 检查方式 |
|---|---|---|
| Web | `http://127.0.0.1:5180/` | 浏览器可打开登录页 |
| Java BFF | `http://127.0.0.1:8200/` | `curl http://127.0.0.1:8200/health` 返回 `UP` |
| Python AI | `http://127.0.0.1:8300/` | `curl http://127.0.0.1:8300/health` 返回 `UP` |
| AI 熔断状态 | `http://127.0.0.1:8200/api/v1/health/ai` | 正常时为 `UP`，各 scope `CLOSED` |

> 共享中间件（MySQL 3306 / Redis 6379 / MinIO 9000·9001）只使用，不重启、不修改。

### 0.2 演示账号

| 账号 | 角色 | 用途 |
|---|---|---|
| `admin` | 管理员 | 全流程、派单、验证、关闭、知识管理 |
| `engineer1` | 工程师（张工） | 接单、处理、提交解决 |
| `reporter1` | 报障人（李业主） | 报修、查看自己的工单 |

密码统一为项目根 `.env` 中的 `DEV_ADMIN_PASSWORD`。**不要把密码写入本文档或截图。**

### 0.3 建议测试数据

- 报修内容：`A栋2号梯困人了，请尽快处理`
- 知识文件：`e2e-elevator.md`，内容见 §5.1
- 记录每次产生的工单号，后续验收以该工单号为准。

## 2. 对话报修与人在回路建单

| 步骤 | 操作 | 预期结果 |
|---|---|---|
| 2.1 | 左侧进入“AI 助手”，点击“新建” | 创建新会话，标题为“AI 助手”或会话号 |
| 2.2 | 输入：`A栋2号梯困人了，请尽快处理`，点击“发送” | 流式输出开始；出现“处理过程”时间线 |
| 2.3 | 观察分诊结果 | 显示“故障报修”、置信度、`生成工单草稿` |
| 2.4 | 观察工单草稿卡 | 标题、类型（电梯）、优先级（紧急）、位置（A栋 2号） |
| 2.5 | 点击“确认建单” | 提示“已创建工单 WT...”；卡片变为“已建单”并显示工单号 |
| 2.6 | 打开“工单管理”，按工单号搜索 | 工单存在，状态为“待受理”，报障人为当前用户 |

**通过标准**：

- AI 回复有流式打字效果，无整段突然出现；
- 分诊卡片可确认/忽略；
- 确认后只创建一张工单（重复点击不会重复建单）；
- 工单详情能看到来源会话/分诊关联。

**异常检查**：点击“忽略”后不应建单；再次发送相同内容应产生新草稿，不应复用旧草稿。

## 3. 工单 AI 初步分析

| 步骤 | 操作 | 预期结果 |
|---|---|---|
| 3.1 | 工单管理 → 打开 §2 创建的工单详情 | 右侧抽屉显示工单详情、SLA、处理人 |

## 4. 派单 → 接单 → 解决 → 验证 → 关闭

### 4.1 管理员派单

| 步骤 | 操作 | 预期结果 |
|---|---|---|
| 4.1.1 | 以 `admin` 登录，工单管理找到 §2 工单 | 状态“待受理” |
| 4.1.2 | 点击“派单” | 弹出派单对话框 |
| 4.1.3 | 选择“张工（运维）”，点击“确定派单” | 提示成功；状态变为“待接单”；处理人为张工 |
| 4.1.4 | 右上角铃铛 | 出现未读通知（工程师收到“工单已派给你”） |

### 4.2 工程师接单与处理

| 步骤 | 操作 | 预期结果 |
|---|---|---|
| 4.2.1 | 退出，使用 `engineer1` 登录 | 能进入系统，菜单不含“知识库” |
| 4.2.2 | 工单管理找到该工单，点击“接单” | 状态变为“处理中” |
| 4.2.3 | 点击“解决” | 弹出“提交解决”，填写服务项目，并**必须拍摄至少一张现场照片** |
| 4.2.4 | 提交 | 状态变为“待验证”；报障人收到通知；未上传照片时提示“请先上传至少一张现场照片” |
| 4.2.5 | 可选：点击“挂起”，填写原因 | 状态“挂起”；再“恢复”后 SLA 到期顺延 |

### 4.3 管理员验证与关闭

| 步骤 | 操作 | 预期结果 |
|---|---|---|
| 4.3.1 | 退出，`admin` 登录，找到该工单 | 状态“待验证” |
| 4.3.2 | 点击“验证通过” | 状态变为“已解决” |
| 4.3.3 | 点击“关闭” | 状态变为“已关闭”；报障人与处理人收到通知 |
| 4.3.4 | 打开工单时间线 | 能看到 CREATED、ASSIGN、ACCEPT、RESOLVE、VERIFY、CLOSE 事件 |
| 4.3.5 | 另建一张测试工单，在非终态点击“结束工单” | 直接置“已关闭”，时间线出现 FINISH 事件 |

**通过标准**：状态流转严格、每次操作有审计/时间线、通知对象正确、非法状态操作被拒绝并给出中文提示。

## 5. 知识入库与 RAG 引用

### 5.1 准备知识文件

新建 `e2e-elevator.md`：

```markdown
# 电梯困人应急处置

1. 立即通过对讲安抚被困人员，确认人数、是否有受伤或身体不适。
2. 通知电梯维保单位与物业值班负责人，记录困人时间与电梯编号。
3. 禁止非专业人员强行扒门或进入井道。
4. 维保到场后按规程救援，恢复前确认门锁、平层与报警装置正常。
5. 救援完成后填写工单处理结果，并回访被困人员。
```

## 7. M8 降级验收（建议执行）

## 10. 常见问题

| 现象 | 检查 |
|---|---|
| 登录后立即回登录页 | 检查 `.env` 的 `JWT_SECRET`、Java 是否重启、浏览器是否清除了存储 |
| AI 无响应 | 检查 8300 `/health`、Java 日志、`/api/v1/health/ai` 是否 `DEGRADED` |
| 知识上传成功但检索不到 | 检查文档状态、分块数、Embedding 配置；查看知识页“刷新” |
| 派单下拉为空 | 检查 `users/options` 接口与 `ticket:read` 权限 |
| 通知不更新 | 当前为 30s 轮询；刷新页面或等待轮询 |
| 停 Python 后无法恢复 | 确认新进程已监听 8300；等待 15s 让熔断半开；查看 `health/ai` |
